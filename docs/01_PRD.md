# Product Requirements Document (PRD) 📋
## Project: Project P (Universal AI Knowledge & Collaborative Resource OS)

---

## 1. วิสัยทัศน์และเป้าหมายของผลิตภัณฑ์ (Product Vision & Goals)

### 1.1 วิสัยทัศน์ (Vision)
สร้างแพลตฟอร์มบริหารจัดการและสังเคราะห์องค์ความรู้ยุคใหม่ที่รองรับ **"ไฟล์อะไรก็ได้ในโลก"** โดยแปลงข้อมูลต้นฉบับให้อยู่ในรูปแบบข้อมูลมาตรฐาน และนำเสนอใหม่เป็น **Semantic HTML หลากรูปแบบ (Document, Presentation, Interactive Table, Image with Vision AI)** ที่ออกแบบมาเพื่อการทำงานร่วมกันอย่างปลอดภัย ด้วยระบบ **Cell-Level Table Locking**, **Shared Temp Draft State (รีเฟรชไม่หาย ทุกคนเห็นตรงกัน)**, **3-Tab Save Modal (ก่อนแก้ / หลังแก้ / หมายเหตุ & ข้อขัดแย้ง)** พร้อมระบบ **Selective Commit**, **Canonical Term Standardization ใน Living Glossary**, และ **การตรวจจับ Conflict ทันทีตอน Generate หรือ Save Resource**

### 1.2 วัตถุประสงค์หลัก (Core Objectives)
1. **Granular Collaboration & Shared Temp Draft:**
   - ในตาราง Sheet ล็อกเฉพาะ Cell/Row ที่กำลังแก้ เพื่อให้แก้ไขพร้อมกันได้หลายคน
   - เมื่อพิมพ์แก้ไขบล็อกเสร็จ ข้อมูลจะถูกจัดเก็บเป็น **Temp State ส่วนกลาง** ทันที รีเฟรชเบราว์เซอร์ไม่หาย และเพื่อนร่วมทีมเห็นการเปลี่ยนแปลงชั่วคราวนี้พร้อมกัน
   - มีปุ่ม **"Revert Block"** ย้อนเฉพาะบล็อกที่ต้องการกลับสู่เวอร์ชันเซฟล่าสุด
2. **3-Tab Save Modal พร้อมระบบเลือก Commit (Selective Staging):**
   - เมื่อกด Save Resource จะเปิดหน้าต่างตรวจสอบ 3 แท็บ:
     - **แท็บ 1: ก่อนแก้ไข (Original):** ข้อความเวอร์ชันทางการล่าสุด
     - **แท็บ 2: หลังแก้ไข (Proposed with Diff):** แสดงสิ่งที่เปลี่ยนแปลง พร้อมแถบสถิติ (`+คำ / -คำ`) และ **Checkbox ให้ติ๊กเลือกเฉพาะบล็อกที่ต้องการ Commit** (บล็อกที่ไม่ติ๊กจะคงสถานะ Temp ไว้ต่อไป)
     - **แท็บ 3: หมายเหตุ & ข้อขัดแย้ง (Notes & Conflicts):** กรอก Commit Message และแสดงผลการตรวจจับข้อเท็จจริงขัดแย้งกับเอกสารอื่น
3. **Conflict Detection บน 2 จังหวะสำคัญ (On Generate & On Save):**
   - ระบบตรวจจับความขัดแย้งจะรันอัตโนมัติ: (1) เมื่อผู้ใช้สั่ง AI สร้างเอกสารใหม่ (Generate Resource) และ (2) เมื่อกดเปิดหน้าต่าง Save Resource
4. **Canonical Term Standardization (ลดความซ้ำซ้อนของคำ):**
   - ระบบ living Glossary จะยุบรวมคำที่มีความหมายเดียวกันแต่เขียนหลายรูป (เช่น Kubernetes, K8s, K8S) ให้เหลือ **คำหลักมาตรฐาน (Canonical Term)** คำเดียว เพื่อไม่ให้เกิดโหนดซ้ำใน Knowledge Base
5. **Knowledge Gap & Orphan Concept Finder:**
   - ตัวกรองใน Knowledge Hub ช่วยตรวจจับคำศัพท์หรือแนวคิดที่ถูกกล่าวถึงในเอกสาร แต่ยังไม่มีเอกสารใดเขียนอธิบายอย่างเป็นทางการ ชี้เป้าให้ทีมสร้างเนื้อหาเพิ่ม
6. **Enhanced Universal Viewers:**
   - **TOC ScrollSpy:** สารบัญด้านข้างเลื่อนไฮไลต์ตามการอ่านจริง
   - **Slide Grid Sorter:** ดู Thumbnail สไลด์ทุกหน้าพร้อมกันเพื่อข้ามไปหน้าที่ต้องการ
   - **Split Mode:** สลับระหว่าง WYSIWYG และ Raw Markdown

## 2. ขั้นตอนการแก้ไขและการบันทึก 3 แท็บ (Shared Temp & 3-Tab Save Modal)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        RESOURCE: "Clinical_Trial_Phase1.html"          │
├────────────────────────────────────────────────────────────────────────┤
│ <p id="p-001"> [เวอร์ชันทางการที่บันทึกแล้ว]                           │
├────────────────────────────────────────────────────────────────────────┤
│ <p id="p-002" class="temp-draft">                                      │
│   🟡 [สถานะ Temp Draft] แก้ไขโดย Somchai (รีเฟรชไม่หาย ทุกคนเห็นตรงกัน) │
│   [ปุ่ม Revert Block] ย้อนเฉพาะบล็อกนี้กลับสู่ค่าเดิมได้               │
├────────────────────────────────────────────────────────────────────────┤
│ <tr id="row-04" class="cell-locked">                                   │
│   🔒 เซลล์ B4 กำลังถูกแก้ไขโดย Somsak (คนอื่นแก้เซลล์อื่นได้ปกติ)      │
└────────────────────────────────────────────────────────────────────────┘
```

### การเปิดหน้าต่างบันทึก 3 แท็บ (3-Tab Save Modal):
เมื่อผู้ใช้กดปุ่ม **"💾 บันทึกเอกสาร (Save Resource)"**:
* **แท็บ 1: ก่อนแก้ไข (Original):** ดูเนื้อหาดั้งเดิมทั้งฉบับ
* **แท็บ 2: หลังแก้ไข (Proposed with Diff):**
  - แถบสถิติด้านบน: `+120 คำ | -30 คำ | เปลี่ยนแปลง 4 บล็อก`
  - กล่องข้อความ Diff (แดง/เขียว) พร้อม Checkbox หน้าแต่ละบล็อก:
    - `[✓] บล็อก 1 (ต้องการบันทึกเป็นเวอร์ชันถาวร)`
    - `[ ] บล็อก 2 (ยังไม่บันทึก -> คงสถานะเป็น Temp ต่อไป)`
* **แท็บ 3: หมายเหตุ & ข้อขัดแย้ง (Notes & Conflicts):**
  - ช่องใส่บันทึกย่อการแก้ไข (Commit Message)
  - แผงตรวจจับข้อเท็จจริงขัดแย้ง: แสดงหากบล็อกใหม่มีตัวเลขหรือเงื่อนไขที่ค้านกับไฟล์อื่นในโปรเจกต์
* เมื่อกดยืนยัน: บล็อกที่ถูกติ๊กจะกลายเป็นเวอร์ชันทางการ บล็อกที่ไม่ถูกติ๊กจะยังคงเป็น Temp และระบบรัน **Incremental Delta Sync** เข้า Knowledge ทันที!

## 3. การลดความซ้ำซ้อนของคำศัพท์ (Canonical Term Standardization)

* เมื่อ AI หรือผู้ใช้เพิ่มคำศัพท์ใน Living Glossary ระบบจะวิเคราะห์คำพ้องและคำย่อ:
  - ตัวอย่าง: คำว่า `K8s`, `k8s`, `Kubernetes Cluster` จะถูกจัดกลุ่มภายใต้ Canonical Term: **`Kubernetes`**
  - ในหน้า Knowledge Graph จะแสดงโหนดเดียวคือ `Kubernetes` เพื่อตัดความซ้ำซ้อน
  - เมื่อผู้อ่านเปิดอ่านเอกสาร ไม่ว่าจะเจอคำว่า "K8s" หรือ "Kubernetes" ตัว Hover Card จะชี้ไปที่นิยามมาตรฐานเดียวกัน

## 4. ตัวค้นหาช่องว่างความรู้ (Knowledge Gap / Orphan Finder)

ในหน้า Knowledge Hub:
* เพิ่มตัวกรอง **"🔍 ช่องว่างความรู้ (Knowledge Gaps)"**
* แสดงรายการเอนทิตีหรือมโนทัศน์ที่มีการเอ่ยถึงในเอกสาร (Mentions) มากกว่า 3 ครั้ง แต่ยังไม่มีเอกสารใดใน Resource บรรยายความหมายหรือเป็นเจ้าของแนวคิดนี้อย่างเป็นทางการ
* มีปุ่มด่วน: **"✨ สั่ง AI ร่างเอกสารอธิบายหัวข้อนี้ (Draft Doc for this Concept)"** เพื่อนำไปบันทึกเป็น Resource ใหม่ปิดช่องว่างความรู้ทันที

---

## 5. การตรวจจับข้อเท็จจริงขัดแย้ง (Conflict Detection Lifecycle)

ระบบตรวจจับ Conflict จะทำงานใน 2 ช่วงเวลาสำคัญ:
1. **ขณะสั่ง AI สร้าง Resource ใหม่ (On Generate):** AI วิเคราะห์เนื้อหาที่ร่างขึ้นใหม่เทียบกับคลัง Resource หากพบจุดค้าน จะเตือนผู้ใช้ก่อนกดยืนยันบันทึกเข้าคลัง
2. **ขณะกดบันทึกเอกสาร (On Save Resource):** แสดงผลลัพธ์ในแท็บที่ 3 ของ Save Modal ทันที
